# Well-Architected Security Pillar

## What are the seven security design principles?
Aliases: Security pillar principles | Seven design principles | Core security principles
Tags: principles, identity, traceability, automation, data-protection
Seven principles: strong identity, traceability, defense in depth, automation, protecting data everywhere, keeping people off data, and readiness for events.

• Strong identity foundation; enable traceability
• Security all layers; automate best practices
• Protect data transit and rest
• Keep people away; prepare events

## What are the security pillar best-practice areas?
Aliases: Security focus areas | Best-practice areas | Security pillar areas
Tags: iam, detection, incident-response, application-security, infrastructure
Seven areas: security foundations, identity and access, detection, infrastructure protection, data protection, incident response, and application security.

• Foundations and IAM control access
• Detection spots threats early
• Infrastructure and data protection layers
• Incident response; application security

## How do you run a Well-Architected security review?
Aliases: Security review process | Running a WAFR | Well-Architected review
Tags: review, war-tool, remediation, hri, workload
Use the Well-Architected Tool to review a workload against the pillar and build a prioritized remediation plan.

• Define workload scope first
• Answer questions, surface risks
• Prioritize high-risk items (HRIs)
• Track remediation, then re-review
