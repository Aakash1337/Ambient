Ambient

Real-time agent assist for live calls. It hears both sides, ignores everything that isn't a real question, and puts a glanceable answer in front of the agent as the external answer model responds. Timing varies by host and network.

The problem

  • Agents put customers on hold to search the knowledge base — the single biggest dead-air driver.
  • New agents take months to ramp; product knowledge lives in a few veterans' heads.
  • Existing "agent assist" tools transcribe everything and suggest constantly — a firehose the agent learns to ignore.

The scarce resource isn't answers. It's the agent's attention, mid-sentence.

What it does

customer + agent audio → local transcription host-dependent → question gate filters noise → answer card streams from Claude → optional audit revises if wrong
  • Passive. It never prompts, never interrupts, never needs a click during a call.
  • Selective. Statements, small talk and rhetoric produce nothing. Only real questions become cards.
  • Defined boundary. Raw audio/STT/primary gating are local; transcript context goes to Claude for answers and recovery.

Hears both sides — no telephony integration

  • The customer is whatever the configured capture input receives: PipeWire monitors, WASAPI loopback, or a virtual CoreAudio input such as BlackHole.
  • The agent is the microphone. The validated Linux host adds noise suppression and auto-gain; that processing is not a macOS claim.
  • Every output endpoint is watched at once; the one carrying speech wins automatically when the call moves between headset and speakers.
  • A channel that goes deaf shows SILENT ⚠ instead of pretending to work.

Prototype-grade integration cost: zero. It works with the dialer you already have.

The question gate is the product

  • Free heuristics answer explicit interrogatives instantly and drop filler, rhetorical tags ("…right?"), and talk aimed at someone else.
  • Uncertain speech goes to a local LLM judge (~0.5 s on the original RTX host; unmeasured on Mac) that catches indirect asks: "I was wondering whether my plan covers roaming."
  • Command-form asks count: "Talk me through the cancellation policy." Operator-channel commands fast-accept; permissive customer-channel commands require the local semantic judge.
  • Per-channel rules: the customer channel is mined freely; the agent's own narration is never mined.

Answers built for glancing

Q  Does the premium plan include international roaming?
A  Yes — Premium includes roaming in 48 countries at no extra charge; data is capped at 5 GB per trip.
  • 48 countries, no add-on needed
  • 5 GB roaming cap per trip
  • Cap raise: +$10 → 15 GB
  • First line is sayable verbatim; bullets are keyword prompts, not paragraphs.
  • Streams word by word as Claude responds; a live audit observed 3.8–21.8 s first-pass end to end.
  • Follow-ups resolve against earlier answers: "and the second option?" A scenario stated before the question constrains the answer.
  • Pricing/version questions trigger a live lookup instead of trusting model memory.

It checks its own work

Answer audit — optional, default off

  • A second pass with a wider context window re-reads each delivered answer.
  • Replaces the card (marked revised) only when materially wrong — missed constraint, misheard question, factual error. Correct cards never flicker.

Missed-question sweeper — every 25 s

  • Judgment-stage rejections get a best-effort second look with wider context.
  • A pre-cap audit saw ~44–210 s recoveries; the current release discards candidates older than 60 s. Neither number is a delivery SLA, and misses remain possible.

Privacy & compliance posture

  • Local: raw audio, Whisper transcription, and the primary Ollama gate. Claude receives no raw audio.
  • External: primary answers receive the accepted turn, recent transcript/history, profile context, and grounding. The default sweep also sends rejected candidates and wider context; optional verification sends more.
  • Web lookup: when triggered, adds outbound search queries and results.
  • Session logs: local plaintext, replayable for QA; git-ignore is not encryption or retention control.
  • Consent: every participant must agree to capture, transcription, logging, and external processing before use.

From prototype to production

  • Knowledge: per-queue profiles today → retrieval over the real KB and policy docs.
  • Workflow: answer cards today → push to CRM/ticket, disposition suggestions, wrap-up summaries from the session log.
  • Audio: desktop capture today → SIP/CTI taps for hard-phone floors; speaker diarization for speakerphone.
  • Models: answer endpoint is one config line — point it at the approved deployment.

The core paths are built and measured on the named development host; each release machine and call route still needs acceptance.
